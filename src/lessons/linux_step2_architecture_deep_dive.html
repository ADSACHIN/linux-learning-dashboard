⚙Kernel Architecture — Monolithic Deep StructurePANEL 01
Monolithic Kernel — What It Really Means
All kernel subsystems run in a single address space (Ring 0 / kernel space) as one large binary. Device drivers, filesystem code, network stack, memory manager, scheduler — all compiled together.

Benefit: zero context-switch overhead between subsystems. A VFS call to ext4 that triggers a block device driver that needs a DMA interrupt — all in kernel space, no IPC, no boundary crossings.

Risk: a bug in any driver can kernel panic the entire system. This is why driver quality matters critically on Linux.
Kernel Space vs User Space
Kernel space = Ring 0. Full CPU privilege. Direct hardware access. Unlimited memory access. One crash = system down.

User space = Ring 3. Restricted. Cannot access hardware directly. Cannot access other processes' memory. One crash = only that process dies.

The boundary is enforced by the CPU's privilege rings. Crossing it requires a system call — a controlled trap into the kernel.
CPU Privilege Rings
x86 defines 4 rings (0–3). Linux uses only 2:
Ring 0 — Kernel. Can execute ANY instruction, access ANY memory.
Ring 3 — User processes. Hardware-enforced sandbox.

Rings 1 & 2 exist but are unused in Linux. Some hypervisors exploit them for virtualisation boundaries.
Kernel Modules (LKM)
Linux supports Loadable Kernel Modules — code that can be dynamically inserted into the running kernel without rebooting.

lsmod — list loaded modules
modprobe — load a module with dependencies
rmmod — remove a module

Device drivers (wifi, GPU, USB) are typically modules. This extends monolithic design without requiring recompilation.

📊CFS Scheduler — Completely Fair SchedulingPANEL 04
How CFS Works
CFS uses a red-black tree (ordered by vruntime) to track all runnable processes. The process with the smallest vruntime runs next — guaranteeing fairness over time.

vruntime increases while a process runs, weighted by nice value (priority). Low-priority tasks accumulate vruntime faster → get less CPU time.
Scheduling Classes (Priority Order)
1. SCHED_DEADLINE — real-time, CBS algorithm
2. SCHED_FIFO — real-time FIFO, runs until yields
3. SCHED_RR — real-time round-robin with timeslice
4. SCHED_NORMAL (CFS) — standard processes
5. SCHED_IDLE — runs only when CPU is idle

◫Memory Management — Virtual Memory & Address SpacePANEL 05
Virtual Memory — Why It Exists
Every process believes it has the entire address space (0x0000 → 0xFFFF…) to itself. The kernel + MMU (Memory Management Unit) transparently map virtual pages → physical page frames.

This enables: process isolation (each has own space), swap (page to disk when RAM full), memory-mapped files (mmap), and ASLR (randomise base addresses).
Page Fault Handling
When a process accesses a virtual address with no physical mapping, the CPU raises a page fault interrupt.

Kernel decides: is this a valid access (page just not loaded)? → allocate physical frame, update page table, resume. Or an invalid access (SIGSEGV)? → kill the process.
x86-64 Process Virtual Address Space Layout
0xFFFF…FFFF
Kernel Space (Ring 0)
kernel code, data, page tables — user cannot access — mapped in every process
↑ grows down
Stack
local variables, function call frames, return addresses — grows toward lower addresses
unmapped (guard region + ASLR randomisation)
↑ grows up
Heap
dynamic allocations (malloc/new) — grows upward — managed by brk()/mmap()
BSS + Data Segment
uninitialised globals (BSS), initialised globals and static variables (data)
low address
Text Segment (Code)
executable instructions — read-only, shared between processes running same binary
0x0000…0000
NULL page (unmapped)
accessing address 0 = SIGSEGV — null pointer dereference protection

📂VFS — Virtual File System LayerPANEL 06
What is VFS?
VFS is an abstraction layer inside the kernel that presents a uniform file API (open, read, write, stat) regardless of the underlying storage format. Whether you read from ext4, XFS, tmpfs, NFS, procfs, sysfs, or even a character device — you always call the same syscalls. VFS dispatches internally to the correct filesystem driver.
VFS Call Chain — open("/etc/passwd")
User Process
glibc open("/etc/passwd", O_RDONLY)
↓ syscall (openat #257)
VFS Layer
do_sys_openat2() → vfs_open()
path resolution, dentry cache lookup, inode lookup
↓ file_operations dispatch
ext4 Driver
ext4_file_open() → reads inode from disk
fetches block group, inode table entry for /etc/passwd
↓ block layer → disk I/O
Block Device
NVMe driver → physical read → page cache
↓ returns fd to user
File Descriptor
fd=3 returned to process — index into fd table

⇄IPC — Inter-Process CommunicationPANEL 07
▶
Pipes (Anonymous)
Unidirectional byte stream between parent and child. Created by pipe() syscall. No filesystem path.
ls | grep .conf | wc -l
⇌
Named Pipes (FIFO)
Pipe with a filesystem path. Unrelated processes can communicate. Persists until deleted.
mkfifo /tmp/mypipe
⚡
Signals
Async notification to a process. Limited data (signal number only). Used for control (stop, kill, reload).
kill -SIGUSR1 <pid>
📬
Message Queues
Kernel-managed message buffer. Typed messages, persistent until removed. POSIX mq or System V.
mq_open("/myqueue", ...)
◫
Shared Memory
Fastest IPC — maps same physical pages into multiple process address spaces. Requires explicit synchronization.
shm_open() / mmap()
🔌
Unix Domain Sockets
Socket API over a filesystem path. Full-duplex. Used by Docker, systemd, Xorg, DBus, PostgreSQL locally.
/var/run/docker.sock
⚠ Security note: Unix domain sockets inherit filesystem permissions. /var/run/docker.sock writable by a user = root-equivalent container escape. Always audit socket permissions: ls -la /var/run/*.sock
🔄Linux Boot Process — BIOS → GRUB → Kernel → systemdPANEL 08
1
BIOS / UEFI — Power-On Self Test
CPU starts at reset vector (0xFFFFFFF0). BIOS/UEFI runs POST: checks RAM, detects hardware, enumerates PCIe devices. UEFI reads GPT partition table and finds EFI System Partition (ESP).
EFI: /boot/efi/EFI/ubuntu/grubx64.efi → hands control to GRUB
2
GRUB2 — GRand Unified Bootloader
GRUB reads /boot/grub/grub.cfg, displays boot menu. Loads compressed kernel image (vmlinuz) and initial RAM disk (initramfs) into memory. Passes kernel parameters.
linux /boot/vmlinuz-6.8.0 root=/dev/nvme0n1p2 ro quiet splash
3
Kernel Decompression + Early Init
Kernel decompresses itself. Sets up memory management, CPU features (CPUID), GDT/IDT, enables paging. Mounts initramfs (tmpfs) as temporary root. Loads essential drivers from initramfs modules.
dmesg | head -20 → see early kernel messages
4
initramfs → Real Root Mount
initramfs runs /init script: loads disk drivers (NVMe, LVM, mdraid), decrypts LUKS if needed, mounts real root filesystem (/dev/nvme0n1p2), pivots root (switch_root).
lsinitramfs /boot/initrd.img-6.8.0 | head -20
5
PID 1 — systemd starts
Kernel executes /sbin/init → symlink → systemd as PID 1. systemd reads unit files. Activates default target (multi-user.target or graphical.target) by resolving dependencies.
systemctl get-default → graphical.target
6
systemd Targets — Service Activation
systemd activates units in parallel: mounts filesystems, starts network, launches daemons (sshd, nginx, cron, docker). Login prompt appears. Total boot time measured by systemd-analyze.
systemd-analyze blame | head -10 → slowest services

⚙systemd — Modern Init System & Service ManagerPANEL 09
systemd Unit Types
.service — daemon processes (nginx.service, sshd.service)
.socket — socket activation (starts service on connection)
.timer — scheduled tasks (replaces cron)
.mount — filesystem mount points
.target — group of units (like runlevels)
.path — triggers on filesystem path change

Targets ↔ SysV Runlevels

rescue.target → runlevel 1 (single user)
multi-user.target → runlevel 3 (no GUI)
graphical.target → runlevel 5 (with GUI)

🔒Security Perspective — Kernel Attack SurfacePANEL 10
Red Team — Kernel & Process Attacks
  • ›Kernel exploits: dirty COW, ptrace abuse, eBPF escapes
  • ›Race conditions in syscall handlers → privilege escalation
  • ›SUID/SGID binaries → run as root without sudo
  • ›IPC socket abuse → /var/run/docker.sock escape
  • ›Memory corruption: heap spray, buffer overflow in kernel modules
  • ›systemd unit misconfiguration → persistent backdoor
Blue Team — Kernel Hardening
  • ›sysctl hardening: ASLR=2, dmesg_restrict=1, kptr_restrict=2
  • ›seccomp profiles: whitelist only needed syscalls (Docker default)
  • ›Capabilities: drop all, grant only required (CAP_NET_BIND_SERVICE)
  • ›systemd service sandboxing: PrivateTmp, NoNewPrivileges, ProtectSystem
  • ›LSM: SELinux or AppArmor mandatory access control policies
  • ›Kernel patches: apply CVE patches, lockdown mode (Secure Boot)

◉Summary — Step 2 CompletePANEL 12
Kernel Architecture
Monolithic design: all subsystems in Ring 0 as one binary. LKMs extend without reboot. CPU rings enforce the user/kernel boundary. Syscalls are the only crossing point.
Process + Memory
CFS scheduler gives each process fair CPU via vruntime red-black tree. Virtual memory isolates processes, enables swap and ASLR. Page faults trigger kernel frame allocation.
Boot + systemd
UEFI → GRUB → vmlinuz → initramfs → PID 1 (systemd). systemd resolves unit dependencies, activates targets in parallel. Service sandboxing is built into unit files.
