📋Linux Logging Architecture — Data FlowPANEL 01
ℹLinux logging is a multi-layer pipeline. Applications write to the kernel audit subsystem, syslog socket, or directly to files. journald aggregates everything into a structured binary journal. rsyslog/syslog-ng can forward to remote SIEMs.

📖journalctl — Structured Log Query EnginePANEL 02
journald vs Traditional syslog
journald stores logs as structured binary — each entry is a JSON-like record with typed fields: _PID, _UID, _COMM, _EXE, SYSLOG_FACILITY, PRIORITY, MESSAGE. You can query on any field, not just regex on text.

Advantages: tamper detection (FSS sealing), rate limiting, structured queries, kernel+user in one store.
Trade-off: binary format — need journalctl to read.
Persistent Journal
By default journal is volatile (lost on reboot). Enable persistent storage:

mkdir -p /var/log/journal
systemd-tmpfiles --create --prefix /var/log/journal

Or set in /etc/systemd/journald.conf:
Storage=persistent

Control size: SystemMaxUse=2G
Control retention: MaxRetentionSec=30d

📡rsyslog — Log Routing, Filtering & Remote ForwardingPANEL 03
rsyslog Architecture
rsyslog reads from /dev/log (syslog socket), journald (imjournal module), and network (imudp/imtcp). Routes messages based on facility.severity rules to files, remote hosts, databases.

Priority: rsyslog config → /etc/rsyslog.conf + /etc/rsyslog.d/*.conf

Facilities: kern(0) user(1) mail(2) daemon(3) auth(4) syslog(5) lpr(6) news(7) local0-7(16-23)
Remote Log Forwarding to SIEM
Forward logs to centralised SIEM (Splunk, Elastic, Graylog) over TCP/TLS.

Why it matters: If attacker compromises host and clears local logs, SIEM retains all events. Non-repudiation of security events.

Protocol: RFC 3164 (legacy) or RFC 5424 (modern, structured). TLS: @@(o)host:6514

🔄Log Rotation — logrotate Configuration & PolicyPANEL 04
ℹWithout log rotation, /var/log/ grows until the disk is full — causing application crashes, service failures, and data loss. logrotate runs daily via cron/systemd timer and rotates, compresses, and prunes old logs automatically.
/etc/logrotate.d/nginx — Annotated Production Config
DIRECTIVEEXPLANATION
/var/log/nginx/*.log {Match all nginx log files
dailyRotate every day. Alternatives: weekly, monthly, size 100M
missingokDon't error if log file missing (service might be stopped)
rotate 30Keep 30 old rotated files before deleting. 30 days of history.
compressCompress rotated files with gzip
delaycompressDon't compress the most recent rotated file — nginx may still write to it
notifemptyDon't rotate empty log files
create 0640 www-data admCreate new empty log with these permissions after rotation
sharedscriptsRun postrotate script once for all matched files (not per file)
postrotateRun after rotation — tell nginx to reopen log files
nginx -s reopenSend USR1 equivalent — nginx closes old FD, opens new file
}

🔬strace, ltrace & perf — Deep Process DebuggingPANEL 07
strace — System Call Tracer
strace intercepts and records all system calls made by a process. Essential for debugging: "why is this program failing?", "what files is it opening?", "why is it slow?", "is it stuck in a syscall?".

Attaches to running processes (-p PID) or starts new ones. Output shows: syscall name, arguments, return value, time spent.

Performance note: strace adds ~5-10x overhead. Don't use in production for extended periods.
perf — Linux Performance Counters
perf uses hardware performance counters (PMU) for low-overhead profiling. Can profile CPU cycles, cache misses, branch mispredictions, page faults, context switches.

perf top — live CPU hotspot (like top but function-level)
perf record — record events for a command
perf report — analyse recorded data
perf stat — event counts summary

🏢Enterprise Troubleshooting Scenarios — Root Cause AnalysisPANEL 09
① High Load Average — Server Unresponsive
Symptom: load avg 28 on 4-core system. SSH barely connects.

Diagnosis:
1. uptime → confirm load
2. vmstat 1 → r=26 (26 waiting for CPU), wa=0 (not I/O)
3. ps aux --sort=-%cpu | head -5 → PID 8841 at 780% CPU
4. cat /proc/8841/cmdline → crypto miner malware
5. strace -p 8841 -e trace=network → mining pool connections
kill -9 8841 && ausearch -k root_commands | grep 8841
② Disk Full — Application Crashes
Symptom: nginx 502 errors. Application logs stop. New files can't be created.

Diagnosis:
1. df -h → /var at 100%
2. du -sh /var/* | sort -rh | head → /var/log = 98GB
3. lsof | grep deleted → 8.1GB deleted log still open by nginx
4. ls -lhS /var/log/nginx/ → access.log is 78GB, no rotation
5. Root cause: logrotate misconfigured, access.log unbounded
nginx -s reopen && logrotate --force /etc/logrotate.d/nginx
③ Memory Leak — OOM Kill Loop
Symptom: Service restarts every few hours. Logs stop abruptly.

Diagnosis:
1. journalctl -u myapp | grep "Out of memory"
2. dmesg | grep "Killed process" → confirms OOM kill
3. sar -r 1 60 → memory growing linearly
4. valgrind --leak-check=full ./myapp 2>&1 | grep "lost"
5. Found: SSL context not freed in connection handler
systemctl set-property myapp.service MemoryMax=512M # immediate mitigation
④ Intermittent 500 Errors — Service Investigation
Symptom: Users report random 500 errors ~every 2 minutes, 5-10s duration.

Diagnosis:
1. tail -f /var/log/nginx/error.log → "upstream timed out"
2. journalctl -u myapp -f → GC pause messages every 2min
3. jstat -gc $(pgrep java) → full GC taking 8s
4. ss -tn state time-wait | wc -l → 24k TIME_WAIT sockets
5. Root cause: Java heap too small → frequent full GC → blocking requests
JAVA_OPTS="-Xmx4G -XX:+UseG1GC" systemctl restart myapp
⑤ Slow Database Queries — I/O Investigation
Symptom: MySQL queries taking 10-30s instead of milliseconds.

Diagnosis:
1. iostat -x 1 → sdb %util=98%, await=180ms
2. iotop -o → mysqld writing 120MB/s continuously
3. strace -e trace=write -p $(pgrep mysqld) → writes to redo log
4. vmstat 1 → wa=45% — I/O bottleneck confirmed
5. Root cause: redo log on HDD instead of SSD after migration
mv /var/lib/mysql/ib_logfile* /ssd/mysql/ && ln -s /ssd/mysql/ /var/lib/mysql/
⑥ SSH Connection Drops — Network/Timeout
Symptom: SSH sessions drop after ~5 minutes of inactivity.

Diagnosis:
1. journalctl -u sshd | grep "Timeout"
2. sshd -T | grep -E "alive|timeout" → ClientAliveInterval=300
3. Network device (firewall/NAT) drops idle connections at 4min
4. tcpdump -i enp3s0 port 22 → keepalive packets sent but dropped by firewall
echo "ClientAliveInterval 60" >> /etc/ssh/sshd_config && systemctl reload sshd

◉Summary — Step 10 CompletePANEL 13
Logging Stack
Applications → journald → rsyslog → files + remote SIEM. journalctl: query by any field, boot, time, priority. rsyslog: route by facility.severity, forward via TLS. logrotate: daily rotation, 30-day retention, postrotate hooks. chattr +a protects log integrity.
Performance Tools
top/htop: real-time process view. vmstat: CPU/swap/I/O snapshot. iostat: per-disk saturation. sar: 30-day historical replay. iotop: I/O per process. nethogs: bandwidth per process. perf: function-level CPU profiling. strace: syscall debugging.
Troubleshooting Method
Layer approach: symptom → metric (top/vmstat) → identify culprit process → deep-dive (strace/lsof/perf) → root cause → fix. Every scenario has a command chain. dmesg for kernel issues. journalctl -b -p err for boot problems. lsof for disk/FD leaks.
