🔄Complete Linux Boot Sequence — Power → Login PromptPANEL 01
ℹLinux boot is a 7-stage pipeline. Each stage hands control to the next. A failure at any stage produces a specific error message that points to the root cause. Understanding each stage is essential for both administration and forensic analysis.
PWR
① Power On — CPU Reset Vector T+0ms
CPU starts at hardwired reset vector address 0xFFFFFFF0 (x86). First instruction executes in real mode (16-bit). Jumps to firmware entry point in flash ROM.
• All CPU registers reset to known state
• Memory controller not yet initialized — only CPU cache as RAM
• No operating system, no drivers — pure hardware state
FW
② BIOS / UEFI Firmware T+10–2000ms
Legacy BIOS: POST (Power-On Self Test) → detect RAM/CPU/PCI → scan disks for MBR at LBA 0 → load 512-byte bootstrap code → jump to it.

UEFI (modern): Full 32/64-bit firmware. Reads GPT partition table → finds EFI System Partition (ESP, FAT32) → loads .efi application (GRUB or Linux EFI stub). Supports Secure Boot signature verification.
UEFI advantages: GPT (no 4-partition/2TB limit), Secure Boot, network boot (PXE), fast boot, driver model, shell environment
efibootmgr -v # show UEFI boot entries and order
GRB
③ GRUB2 Bootloader T+2–4s
GRUB (GRand Unified Bootloader) is a full mini-OS. Loads its own modules from /boot/grub/. Presents boot menu. Reads grub.cfg for menu entries. Loads selected kernel (vmlinuz) and initial RAM disk (initramfs) into memory. Passes kernel command line parameters.
GRUB stages:
• Stage 1: tiny code in MBR/EFI — just enough to load Stage 2
• Stage 2: /boot/grub/core.img — full filesystem drivers, config parser, module loader
• Supports: ext4, xfs, btrfs, LVM, RAID, LUKS, network boot
cat /boot/grub/grub.cfg | grep -A5 "menuentry"
KRN
④ Kernel Loading & Early Init T+4–5s
GRUB decompresses vmlinuz (bzImage = compressed kernel) into RAM. Kernel head.S sets up GDT/IDT, enables protected mode, then long mode (64-bit). Initialises: CPUID detection, memory maps (from BIOS/UEFI), early page tables, console.
• start_kernel() called — C code begins
• Set up per-CPU data, NUMA, SMP
• Initialise subsystems: memory manager, VFS, scheduler, network
• Mount initramfs as temporary root
• Kernel parameters processed (from GRUB command line)
cat /proc/cmdline # see what kernel parameters were passed
RAM
⑤ initramfs — Initial RAM Filesystem T+5–6s
initramfs is a compressed CPIO archive embedded alongside the kernel. Kernel extracts it into a tmpfs (RAM-based) filesystem and mounts it as root (/). The /init script (or systemd) runs as PID 1 in this environment.
initramfs responsibilities:
• Load disk drivers (nvme, virtio, scsi)
• Assemble software RAID (mdadm)
• Open LVM volume groups
• Decrypt LUKS-encrypted partitions (prompts for passphrase)
• Mount real root filesystem
• pivot_root / switch_root to real root
lsinitramfs /boot/initrd.img-$(uname -r) | head -20 # list initramfs contents
SYS
⑥ Real Root Mount → systemd PID 1 T+6–8s
After switch_root, kernel executes /sbin/init (symlink to systemd) as PID 1. systemd reads unit files, builds dependency graph, activates default target in parallel. Socket activation means services are ready before they're fully started.
PID 1 responsibilities (systemd):
• Mount /proc, /sys, /dev (devtmpfs)
• Read /etc/fstab → mount all configured filesystems
• Start networking, udev (hotplug), hostname setup
• Activate target units: sysinit → basic → multi-user / graphical
systemctl get-default # which target is default?
✓
⑦ Login Prompt / Desktop T+8–15s
getty spawns on TTYs → login prompts for credentials → PAM authenticates → shell spawns with user environment. For graphical: display manager (GDM/LightDM) starts → desktop session. System fully operational.
systemd-analyze time # total boot time breakdown
💾BIOS vs UEFI — Architecture Deep ComparisonPANEL 02
Legacy BIOS (Basic Input/Output System)
Written in 1975 for IBM PC. Runs in 16-bit real mode. Disk layout: MBR (Master Boot Record) at LBA 0.

MBR limitations:
• Only 512 bytes for bootstrap code
• Max 4 primary partitions
• Max disk size: 2TB (32-bit LBA)
• No signature verification
• No network boot without option ROM
• Slow (serial device initialisation)
UEFI (Unified Extensible Firmware Interface)
Intel-designed successor. Runs in 32/64-bit protected mode. Disk layout: GPT (GUID Partition Table).

UEFI advantages:
• GPT: up to 128 partitions, 9.4ZB disk
• EFI applications (.efi): full OS-like environment
• Secure Boot: signature chain verification
• Network stack built-in (PXE without ROM)
• Human-readable boot manager
• Parallel device initialisation (faster)
Disk Partition Table Comparison
MBR Disk Layout (Legacy BIOS)
LBA 0 — MBR (512 bytes)
446B bootstrap code + 64B partition table (4 entries) + 2B signature (0x55AA)
Primary Partition 1 — /boot (ext4)
Primary Partition 2 — / (ext4)
Extended Partition → Logical Partitions
Workaround for 4-partition limit
swap
⚠ Max 4 primary partitions. Max 2TB. No signature verification.
GPT Disk Layout (UEFI)
LBA 0 — Protective MBR (legacy compat)
LBA 1 — GPT Header (GUID, CRC32)
LBA 2–33 — Partition Table (128 entries)
EFI System Partition (ESP) — FAT32
/boot/efi — contains .efi bootloaders, shim, kernels
/boot (ext4) — kernel, initramfs, grub
/ (ext4/xfs) — root filesystem
swap / home / data partitions…
LBA -33 to -1 — Backup GPT Header
GPT is duplicated at end of disk for recovery
✓ Up to 128 partitions. 9.4ZB max. CRC32 integrity. Backup copy. GUID per partition.

🥾GRUB2 — Bootloader Internals & ConfigurationPANEL 03
GRUB2 Architecture
GRUB2 is a full-featured bootloader with its own module system, filesystem drivers (ext4, xfs, btrfs, LVM, LUKS), scripting language, and network stack. It can boot Linux, Windows, other GRUB instances, and directly chain EFI apps.

Key files:
/boot/grub/grub.cfg — generated config (never edit directly)
/etc/default/grub — user settings
/etc/grub.d/ — scripts that generate grub.cfg
update-grub / grub-mkconfig — regenerate grub.cfg

⚙Kernel Loading — vmlinuz, Early Init & Memory LayoutPANEL 04
vmlinuz — Compressed Kernel Image
vmlinuz = "virtual memory Linux compressed". It's a bzImage (big zImage) — the kernel compressed with gzip/lzma/xz inside a self-extracting wrapper.

Structure: boot sector + setup code + compressed kernel

When GRUB loads it: the stub extractor runs first, decompresses the real kernel into RAM, then jumps to kernel entry point (startup_64 for x86-64).
Kernel Parameters — start_kernel()
After CPU setup, kernel calls start_kernel() — the main C entry point:
setup_arch() — architecture init (x86 specifics)
mm_init() — memory manager, page allocator
sched_init() — process scheduler (CFS)
vfs_caches_init() — VFS layer setup
rest_init() → spawns kthreadd (PID 2) and calls kernel_init() (→ PID 1)

MBR / Bootloader (Legacy only)
BIOS loads MBR here — 512 bytes. History: IBM PC convention from 1981.

📦initramfs — Initial RAM Filesystem Deep DivePANEL 05
Why initramfs Exists
The kernel needs drivers to access the root filesystem, but those drivers might be modules (.ko files) ON the root filesystem — a chicken-and-egg problem.

Solution: initramfs contains the minimum drivers needed to find and mount the real root. After mounting real root, it performs switch_root — pivots the filesystem tree and execs PID 1 from the real root.

It also handles LUKS decryption (passphrase prompt before root mounts), RAID assembly, LVM activation, and network boot.
initramfs Contents
/init — entry point (script or systemd binary)
/bin/ — busybox: sh, mount, ls, cryptsetup, lvm
/lib/modules/ — only needed kernel modules (.ko)
/etc/ — minimal: crypttab, mdadm.conf
/scripts/ — hook scripts for local/nfs/iscsi mount

Built by: update-initramfs (Debian/Ubuntu) or dracut (RHEL/Fedora)

🔒Secure Boot — Chain of Trust ArchitecturePANEL 07
ℹSecure Boot ensures every component in the boot chain is cryptographically signed and verified before execution. A compromised bootloader or kernel cannot load without a valid signature — this prevents bootkits and UEFI rootkits.
UEFI Firmware
Contains Platform Key (PK) + Key Enrollment Key (KEK) + DB (allowed) + DBX (revoked)
↓ verifies signature against DB
shim.efi (Microsoft-signed)
Pre-signed by Microsoft CA → trusted by all UEFI implementations. Contains distro's Machine Owner Key (MOK).
↓ verifies signature against MOK DB
grubx64.efi (distro-signed)
GRUB signed by distro's key (Ubuntu/RHEL CA). Shim verifies before executing.
↓ verifies kernel signature
vmlinuz (distro-signed kernel)
Kernel image signed with distro key. GRUB verifies before loading.
↓ kernel enforces (lockdown mode)
Kernel Lockdown Mode
Prevents unsigned module loading, /dev/mem access, kexec unsigned kernels, hibernation (could bypass LUKS).

🔧Boot Troubleshooting — Common Failures & RecoveryPANEL 08
① GRUB "error: no such partition" GRUB
GRUB config references a partition UUID that no longer exists. Happens after: disk replacement, partition resize, disk letter change.

GRUB rescue shell appears:
grub rescue> set root=(hd0,gpt2)
grub rescue> set prefix=(hd0,gpt2)/boot/grub
grub rescue> insmod normal && normal
# Then boot normally and run: update-grub
② "Kernel panic — not syncing: VFS: Unable to mount root" KERNEL
Kernel cannot find/mount root filesystem. Causes: wrong root= in cmdline, missing driver in initramfs, corrupted filesystem, LUKS not opened.
# Boot live USB → mount root partition:
mount /dev/nvme0n1p3 /mnt
chroot /mnt
update-initramfs -u # rebuild with correct drivers
update-grub # fix root= parameter
③ Boots to Emergency/Rescue Target SYSTEMD
systemd dropped to emergency target. Causes: FS in /etc/fstab that can't be mounted (wrong UUID after disk swap), FS errors.
# Check which unit failed:
systemctl status
journalctl -xb # boot logs
# Common fix: edit /etc/fstab
blkid # get correct UUIDs
# Remove/comment bad fstab entry
systemctl daemon-reload && exit
④ Service Fails to Start After Boot SERVICE
A critical service (database, webserver) fails to start on boot. Can be dependency issue, config error, missing file, wrong permissions.
systemctl status myservice.service
journalctl -u myservice -b # logs from this boot
systemctl list-dependencies myservice
# Fix: check ExecStart path, permissions,
# ensure After= dependencies are correct
⑤ "fsck" — Filesystem Corruption FS
Filesystem errors detected during boot. ext4 journal may not fully recover after power loss. Boot may pause for manual fsck.
# Unmount first (or use live USB)
fsck -y /dev/nvme0n1p3 # -y = auto-fix
# Force fsck on next boot:
touch /forcefsck # old method
tune2fs -C 99 /dev/nvme0n1p3 # set mount count high
⑥ LUKS Passphrase Prompt Hangs / Missing LUKS
LUKS-encrypted root doesn't prompt for passphrase. Cause: cryptsetup missing from initramfs, wrong PARTUUID in crypttab, no console configured.
# Rebuild initramfs with cryptsetup:
echo "CRYPTSETUP=y" >> /etc/cryptsetup-initramfs/conf-hook
update-initramfs -u
# Verify crypttab entry:
cat /etc/crypttab # must match partition UUID

🔒Security Perspective — Boot-Level Attacks & DefencesPANEL 10
Boot-Level Attack Vectors
  • ›
    Evil maid attack: Physical access → replace bootloader with malicious version → capture disk encryption passphrase. Secure Boot + TPM measured boot prevents this.
  • ›
    UEFI rootkit: Malware persists in UEFI flash storage — survives OS reinstall and disk wipe. Extremely hard to detect. Seen in Lojax (APT28), CosmicStrand (APT41).
  • ›
    Boot parameter manipulation: Append init=/bin/bash to kernel cmdline at GRUB → root shell without authentication. Physical access to reboot = root access.
  • ›
    initramfs backdoor: Replace initramfs with malicious version → extract root encryption key → install persistent backdoor before OS starts.
  • ›
    Live USB bypass: Boot from attacker-controlled USB → mount host disk → bypass all OS-level security. Mitigate: disable USB boot in UEFI + password-protect UEFI settings.
Boot-Level Defences
  • ›
    Enable Secure Boot — prevents unsigned bootloader/kernel execution. Verify with mokutil --sb-state.
  • ›
    LUKS full disk encryption — even if attacker boots from USB and copies disk, data is encrypted without passphrase/keyfile.
  • ›
    GRUB password: grub-mkpasswd-pbkdf2 → require password to edit GRUB entries or boot into rescue. Prevents cmdline manipulation.
  • ›
    UEFI firmware password + disable boot from USB/CD in UEFI settings. Prevents live USB attacks.
  • ›

◉Summary — Step 8 CompletePANEL 13
Boot Chain
7 stages: CPU reset → UEFI POST → GRUB → vmlinuz decompress → initramfs pivot → systemd PID 1 → services. Each stage hands control to the next. A failure at any stage has a specific diagnostic signature visible in dmesg or journalctl -b.
GRUB + initramfs
GRUB reads grub.cfg, loads kernel + initramfs. initramfs solves the chicken-and-egg: contains drivers to find real root. Critical for LUKS/RAID/LVM. update-grub and update-initramfs are the two most important recovery commands.
Security & Recovery
Secure Boot: UEFI → shim → GRUB → kernel chain. GRUB password prevents cmdline attacks. LUKS + TPM = disk stays encrypted even with physical access. chroot from live USB = universal recovery method. systemd-analyze = boot performance audit.
